# 知识图谱入门

## 什么是知识图谱

知识图谱（Knowledge Graph）是一种结构化的语义知识库，用于描述物理世界中的概念及其相互关系。它以图结构存储知识，节点代表实体（如人、地点、事件），边代表实体之间的关系（如"出生于"、"工作于"、"属于"）。

2012 年，Google 正式提出"Knowledge Graph"概念，用于增强搜索引擎结果。如今，知识图谱已广泛应用于智能问答、推荐系统、金融风控、医疗知识管理等领域。

## 知识图谱的核心概念

### 实体（Entity）

实体是知识图谱中的基本单元，代表现实世界中的对象或概念。例如：
- 人物实体：爱因斯坦、屠呦呦
- 地点实体：北京、巴黎
- 机构实体：清华大学、中国科学院
- 概念实体：相对论、青蒿素

### 关系（Relation）

关系连接两个实体，描述它们之间的语义关联。常见关系类型包括：
- 出生于（爱因斯坦 出生于 乌尔姆）
- 工作于（屠呦呦 工作于 中国中医科学院）
- 发现了（屠呦呦 发现了 青蒿素）
- 属于（青蒿素 属于 药物）

### 属性（Attribute）

属性描述实体的特征或状态，以键值对形式表示。例如：
- 爱因斯坦：出生日期 = 1879-03-14
- 北京：人口 = 2154 万
- 相对论：提出年份 = 1905

## 知识图谱的构建流程

### 1. 知识抽取

知识抽取是从原始数据中提取实体、关系和属性的过程，主要包括：

- **命名实体识别（NER）**：识别文本中的实体，如人名、地名、机构名。
- **关系抽取（Relation Extraction）**：判断实体之间的语义关系。
- **属性抽取（Attribute Extraction）**：提取实体的特征信息。

传统方法依赖规则和特征工程，现代方法则广泛使用深度学习模型，如基于 BERT 的序列标注和关系分类模型。近年来，大语言模型（LLM）也被用于知识抽取，通过提示工程引导模型输出结构化的实体和关系。

### 2. 知识融合

知识融合将来自多个来源的知识进行整合，解决实体歧义、重复和冲突等问题。核心任务包括：

- **实体对齐（Entity Alignment）**：判断不同数据源中的两个实体是否指向同一对象。例如，"北京"和"Beijing"应被识别为同一城市。
- **实体消歧（Entity Disambiguation）**：区分同名实体。例如，"苹果"可能指水果公司或水果。

### 3. 知识存储

知识图谱通常使用图数据库存储，常见选择包括：

- **Neo4j**：最流行的原生图数据库，支持 Cypher 查询语言。
- **PostgreSQL + pgvector**：关系型数据库扩展向量支持，适合同时需要结构化查询和向量检索的场景。
- **JanusGraph**：分布式图数据库，适合大规模知识图谱。

## 知识图谱的应用

### 智能问答

知识图谱为问答系统提供结构化知识支持。当用户提问"爱因斯坦出生于哪里？"时，系统可以在知识图谱中查找"爱因斯坦"节点的"出生于"关系，直接返回答案"乌尔姆"。

### 推荐系统

知识图谱可以增强推荐系统的可解释性和准确性。通过分析用户兴趣实体与商品实体之间的关系路径，系统可以给出更精准的推荐，并解释推荐理由。

### 金融风控

在金融领域，知识图谱用于识别企业之间的关联关系，发现潜在风险。例如，通过分析企业间的担保关系链，可以识别出互保风险。

## 向量检索与知识图谱的结合

现代知识图谱系统通常结合向量检索（Vector Search）技术，实现语义级别的搜索。

### Embedding 与向量化

通过 Embedding 模型（如 OpenAI Embedding、SiliconFlow 等），可以将文本转换为高维向量。语义相似的文本在向量空间中距离更近。

### 混合检索

将结构化图查询与向量语义检索结合，可以同时利用知识图谱的结构化关系和文本的语义信息，提供更全面、更准确的检索结果。

## 总结

知识图谱是组织和表示知识的重要方式。随着深度学习和大型语言模型的发展，知识图谱的构建和应用正在变得更加智能和高效。向量检索与知识图谱的结合，为下一代知识管理系统开辟了新的可能性。
