## CC，请执行以下任务：M3.9 — 图谱渲染重构（G6 v5）

M3.8 已完成。本次任务将基于 ECharts 的知识图谱渲染**完全替换**为基于 G6 v5 的增量式图谱浏览器。

**背景**：当前 ECharts 图谱在实体数量增多时全量重绘导致卡顿、交互不流畅。本次重构采用 G6 v5 的增量渲染能力，实现“单击展开邻域”的探索式图谱浏览。

---

## 一、核心设计决策

### 1.1 为什么替换 ECharts

| 问题 | ECharts | G6 v5 |
|------|---------|-------|
| 增量展开 | 不支持，每次全量重绘 | `graph.addData()` 原生支持 |
| 坐标保持 | 重绘后坐标丢失 | 旧节点 `fx/fy` 固定，仅新节点布局 |
| 交互扩展 | 有限 | Behavior 插件化，易于定制 |
| 大图性能 | 节点>200时明显卡顿 | 节点>2000时才需降级 |

### 1.2 与本项目数据结构的对接

本项目已有 `entities` 表和 `relations` 表，本次重构直接使用这些数据：

| G6 概念 | 本项目数据 | 说明 |
|---------|-----------|------|
| Node | Entity | `filter_action='keep'` 的实体 |
| Edge | Relation | 实体间的关系 |
| Node ID | Entity.id | UUID |
| Edge ID | Relation.id | UUID |
| Node Label | Entity.name | 实体名称 |
| Node Type | Entity.type | concept/theorist/theory/method/fact |
| Edge Label | Relation.relation_type | contains/causes/contrasts/precedes/applies_to |

### 1.3 核心交互（三个功能）

| 编号 | 交互动作 | 系统行为 |
|------|----------|----------|
| **F1** | 单击节点 | 向外部拉取该节点的 1 跳邻居（按权重取 Top 10），增量添加到画布。超过 10 个时折叠为虚拟节点「更多...」。已展开过的节点再次单击不重复请求。 |
| **F2** | Shift + 依次点击节点 A 和 B | 计算 A→B 的最短路径，路径高亮显示，页面底部状态栏输出路径文本。 |
| **F3** | 鼠标悬停节点 | 悬停区域内的节点自动疏解（鱼眼效果），避免标签重叠。 |

**辅助功能**：Ctrl+Z 撤销展开。

```
GET /api/graph/neighbors?entity_id={entity_id}&limit=10
```

**响应**：

```json
{
  "entity": {
    "id": "uuid",
    "name": "自我意识",
    "type": "concept"
  },
  "neighbors": [
    {
      "entity": {
        "id": "uuid",
        "name": "自我概念",
        "type": "concept",
        "overall_score": 0.82
      },
      "relation": {
        "id": "uuid",
        "relation_type": "contains",

      }
    }
  ],
  "has_more": false,
  "total_count": 5
```

**限制**：
- 只返回 `filter_action='keep'` 的实体
- 按 `overall_score` 降序排列，取前 `limit` 个
- 如果邻居数 > `limit`，返回 `has_more: true`

**接口2：查询路径**

```
GET /api/graph/path?from={entity_id}&to={entity_id}
```

**响应**：

```json
{
  "path": ["uuid1", "uuid2", "uuid3"],
  "edges": [
    {"from": "uuid1", "to": "uuid2", "label": "contains"},
    {"from": "uuid2", "to": "uuid3", "label": "causes"}
  ],
  "text": "自我意识 → 包含 → 自我概念 → 导致 → 自我评价"
}
```

**实现说明**：路径计算直接在 PostgreSQL 中执行递归查询或在前端用 BFS，由性能决定。

### 5.2 增量展开

```typescript
// useExpand.ts
async function expandNode(nodeId: string) {
  // 1. 检查是否已展开
  if (graphStore.expandedIds.has(nodeId)) return
  
  // 2. 请求邻域数据
  const data = await fetchNeighbors(nodeId, 10)
  
  // 3. 记录历史
  graphStore.pushHistory({
    type: 'expand',
    nodeId,
    addedIds: data.neighbors.map(n => n.entity.id)
  })
  
  // 4. 增量添加到画布
  const addedData = {
    nodes: data.neighbors.map(n => ({
      id: n.entity.id,
      data: {
        label: n.entity.name,
        type: n.entity.type,
        score: n.entity.overall_score
      }
    })),
    edges: data.neighbors.map(n => ({
      id: n.relation.id,
      source: nodeId,
      target: n.entity.id,
      data: {
        label: n.relation.relation_type
      }
    }))
  }
  
  // 5. 使用 addData，禁止 setData
  await graphInstance.addData(addedData)
  
  // 6. 旧节点固定，新节点布局
  await graphInstance.layout()
  
  // 7. 标记为已展开
  graphStore.expandedIds.add(nodeId)
}
```

### 5.3 路径计算与高亮

```typescript
// usePathFinder.ts
async function findPath(fromId: string, toId: string) {
  // 获取当前可见子图的所有节点和边
  const subgraph = getVisibleSubgraph()
  
  // 前端计算最短路径（BFS/双向BFS）
  const path = bidirectionalBFS(subgraph, fromId, toId)
  
  if (path) {
    // 高亮路径
    graphInstance.setItemState(path.nodes, 'highlight', true)
    graphInstance.setItemState(path.edges, 'highlight', true)
    
    // 输出路径文本
    const text = formatPathText(path)
    emit('path-found', text)
  }
}
```

## 六、后端接口实现

### 6.1 邻域查询

```python
# backend/app/routes/graph.py

@router.get("/neighbors")
async def get_neighbors(
    entity_id: str,
    limit: int = 10,
    offset: int = 0,
    db: Session = Depends(get_db)
):
    # 1. 获取该实体的信息
    entity = db.query(Entity).filter(
        Entity.id == entity_id,
        Entity.filter_action == 'keep'
    ).first()
    if not entity:
        raise HTTPException(404, "Entity not found")
    
    # 2. 获取邻居（只返回 keep 状态的实体）
    # 从 relations 表中查询 source 或 target 为该实体的关系
    relations = db.query(Relation).filter(
        (Relation.source_entity_id == entity_id) | 
        (Relation.target_entity_id == entity_id)
    ).all()
    
    # 3. 提取邻居实体
    neighbor_ids = set()
    for r in relations:
        if r.source_entity_id == entity_id:
            neighbor_ids.add(r.target_entity_id)
        else:
            neighbor_ids.add(r.source_entity_id)
    
    neighbors = db.query(Entity).filter(
        Entity.id.in_(neighbor_ids),
        Entity.filter_action == 'keep'
    ).all()
    
    # 4. 按 overall_score 排序，取 limit
    neighbors_sorted = sorted(neighbors, key=lambda e: e.overall_score or 0, reverse=True)
    paginated = neighbors_sorted[offset:offset + limit]
    has_more = len(neighbors_sorted) > offset + limit
    
    # 5. 构建响应
    result = {
        "entity": entity_to_dict(entity),
        "neighbors": [
            {
                "entity": entity_to_dict(n),
                "relation": relation_to_dict(find_relation(entity_id, n.id))
            }
            for n in paginated
        ],
        "has_more": has_more,
        "total_count": len(neighbors_sorted)
    }
    return result
```

```python
    db: Session = Depends(get_db)
```
