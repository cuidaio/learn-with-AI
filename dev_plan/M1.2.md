### 一、L1 边界检测引擎（`l1_boundary_detector.py`）—— 新建文件

在 `backend/app/core/l1_boundary_detector.py` 中实现以下函数：

#### 1.1 `detect_topic_boundaries(text: str) -> List[BoundaryCandidate]`

**三层检测叠加，输出候选边界列表：**

**第一层：词汇分布变化检测（主策略，权重 0.5）**

```
算法：
1. 将文本按句子分割（使用容错句分割：先按 。！？；\n 分割，不足则按 ，、 补充）
2. 对每个句子，提取关键词（去除停用词后的 TF-IDF Top 5）
3. 设置滑动窗口 W = 3 句，计算窗口内词汇分布的 Jaccard 相似度
4. 当相邻窗口相似度 < 阈值 T（动态计算：取全文中位数的 0.6 倍），标记为边界候选
```

**实现细节：**
- 停用词表使用 `jieba.analyse` 的默认停用词
- Jaccard 相似度计算：`|A ∩ B| / |A ∪ B|`
- 输出：`(position: int, confidence: float, source: "vocabulary_shift")`

**第二层：句子连续性评分（辅助策略，权重 0.3）**

```
算法：
1. 对每个相邻句对 (Si, Si+1)：
   a. 计算关键词重合率：intersect(Si.keywords, Si+1.keywords) / min(len(Si.keywords), len(Si+1.keywords))
   b. 计算 Embedding 余弦相似度（可选，如果 API 可用）
2. 当连续 3 个句对的 avg_score < 阈值（0.3），标记边界候选
```

**实现细节：**
- 关键词提取复用第一层的结果
- Embedding 相似度作为“可选增强”——如果 Embedding API 调用失败，只用关键词重合率
- 输出：`(position: int, confidence: float, source: "continuity_drop")`

**第三层：长度强制约束（兜底策略，权重 1.0）**

```
算法：
1. 强制保证每个 L1 块在 [MIN_SECTION_SIZE, MAX_SECTION_SIZE] 范围内
2. 如果某个区间 > MAX_SECTION_SIZE，在区间内寻找优先级最高的次优边界：
   - 优先使用 vocabulary_shift 置信度 > 0.5 的边界
   - 次优先使用 continuity_drop 置信度 > 0.5 的边界
   - 兜底：在区间 2/3 位置强制切分（标记为 forced）
3. 如果某个区间 < MIN_SECTION_SIZE，与相邻区间合并
```

**输出格式：**

```python
@dataclass
class BoundaryCandidate:
    position: int  # 在 cleaned_text 中的字符位置
    confidence: float  # 0-1，综合置信度
    source: str  # "vocabulary_shift" | "continuity_drop" | "forced"
    is_forced: bool = False
```

#### 1.2 `resolve_boundaries(candidates: List[BoundaryCandidate]) -> List[int]`

**边界解析与冲突解决：**

1. 合并位置相近的边界（距离 < 50 字符时，保留置信度更高的）
2. 按位置排序，去重
3. 应用长度约束（第三层），生成最终边界列表
4. 返回字符位置列表

### 二、L2 切分逻辑调整（`chunking.py`）

**删除现有的 `build_paragraph_blocks()` 函数中的 SemanticChunker 逻辑。**

**替换为以下逻辑：**

#### 2.1 `extract_paragraph_candidates(text: str) -> List[ParagraphCandidate]`

**基于可观察的段落边界预切分：**

```
算法（按优先级依次尝试）：
1. 空行分割：\n\n → 段落候选
2. 缩进分割：行首有 2 个以上空格或 \t → 段落候选
3. 对话标记分割：行首有 "「"、"『"、"“" → 段落候选
4. 引用标记分割：行首有 ">"、"|" → 段落候选
5. 如果上述均失败 → 将整个文本作为一个段落候选
```

**输出：**

```python
@dataclass
class ParagraphCandidate:
    content: str
    start_pos: int
    end_pos: int
    source: str  # "blank_line" | "indent" | "dialog" | "quote" | "fallback"
```

#### 2.2 `merge_and_split_paragraphs(candidates: List[ParagraphCandidate]) -> List[ParagraphBlock]`

**长度约束合并/拆分：**

```
规则：
1. 合并阶段：从前往后遍历
   - 如果当前候选长度 < MIN_PARAGRAPH_SIZE，与下一个候选合并（累加长度）
   - 合并后再次检查，直到长度 >= MIN_PARAGRAPH_SIZE
   - 如果合并后长度 > MAX_PARAGRAPH_SIZE，则按句子边界拆分（使用容错句分割）
2. 拆分阶段：
   - 如果候选长度 > MAX_PARAGRAPH_SIZE，在内部找语义断点拆分：
     a. 优先在句子边界拆分（句号、问号、感叹号、分号）
     b. 次优在逗号、顿号位置拆分
     c. 兜底：在 MAX_PARAGRAPH_SIZE 位置强制拆分（标记为 forced）
3. 每个输出块记录：
   - content: str
   - start_pos: int
   - end_pos: int
   - block_index: int（在 L1 块内部的序号）
   - strategy: str（"merged" | "split" | "original" | "forced"）
   - metadata: dict（记录来源候选的 source 和合并/拆分的子块数量）
```

#### 2.3 修改主入口函数 `chunk_document()`

```
新流程：
1. 调用 detect_topic_boundaries() 获取 L1 边界
2. 根据边界切分 L1 块
3. 对每个 L1 块：
   a. 调用 extract_paragraph_candidates() 预切分
   b. 调用 merge_and_split_paragraphs() 合并/拆分
   c. 对每个 L2 块，调用 Embedding API 生成向量
4. 返回 L1 和 L2 结果
```

### 三、结构信号的降级处理（`preprocess.py` 调整）

**在 `extract_structure_signals()` 中增加以下逻辑：**

#### 3.1 结构信号不再作为骨架，而是作为边界置信度的“加权因子”

```
规则：
1. 如果检测到结构信号（标题、章节号），将其位置作为额外的边界候选
2. 该边界的置信度 = 信号置信度 × 0.7（低于词汇分布的 0.5 权重，仅作辅助）
3. 在 resolve_boundaries() 中，将结构信号边界与词汇/连续性边界融合
4. 如果结构信号与词汇边界位置距离 < 100 字符，置信度相加（增强）
5. 如果结构信号与词汇边界位置距离 > 200 字符，结构信号被忽略（不作为边界）
```

**核心变化：** 结构信号不再强制切分，只在“与文本内在信号一致”时才增强边界可信度。
