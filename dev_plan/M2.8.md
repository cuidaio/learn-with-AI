## 一、核心设计原则

1. **知识图谱基于实体-关系三元组**，而非聚类树
2. **增量更新**：每个文档独立编译，后续通过实体解析实现跨文档融合
3. **出题基于结构化事实链**，而非文本拼接
4. **LLM调用范围与文档变化对齐**（新增/修改的文档才消耗token）

## 二、数据模型（新增/修改）

### 2.1 Document 表增加生命周期状态

```sql
ALTER TABLE documents ADD COLUMN lifecycle_status VARCHAR(20) DEFAULT 'new';
-- 枚举值: 'new' | 'modified' | 'unchanged' | 'deleted'
ALTER TABLE documents ADD COLUMN processed_at TIMESTAMP;
```

### 2.2 Entity 表（新增）

```sql
CREATE TABLE entities (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    entity_type VARCHAR(50),  -- 'concept' | 'theorist' | 'theory' | 'method' | 'fact'
    description TEXT,          -- 简短描述（由LLM生成）
    confidence FLOAT DEFAULT 1.0,
    created_at TIMESTAMP DEFAULT NOW(),
    metadata JSONB DEFAULT '{}'::jsonb
);

CREATE INDEX idx_entities_document_id ON entities(document_id);
CREATE INDEX idx_entities_name ON entities(name);
```

### 2.3 Relation 表（新增）

```sql
CREATE TABLE relations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    source_entity_id UUID NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
    target_entity_id UUID NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
    relation_type VARCHAR(50) NOT NULL,  -- 'is_a' | 'contains' | 'causes' | 'contrasts' | 'precedes' | 'applies_to' | 'develops'
    description TEXT,                     -- 关系描述
    confidence FLOAT DEFAULT 1.0,
    created_at TIMESTAMP DEFAULT NOW(),
    metadata JSONB DEFAULT '{}'::jsonb
);

CREATE INDEX idx_relations_source ON relations(source_entity_id);
CREATE INDEX idx_relations_target ON relations(target_entity_id);
CREATE INDEX idx_relations_document_id ON relations(document_id);
```

### 2.4 Question 表（新增）

```sql
CREATE TABLE questions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    knowledge_node_id UUID,  -- 暂时为NULL，后续关联到知识节点（M2.9）
    
    question_type VARCHAR(20) NOT NULL,  -- 'fill' | 'short_answer' | 'essay'
    stem TEXT NOT NULL,
    answer TEXT NOT NULL,
    explanation TEXT,
    
    bloom_level VARCHAR(20),  -- 'remember' | 'understand' | 'apply' | 'analyze' | 'evaluate'
    difficulty_estimate FLOAT,  -- 0-1，LLM预估值
    difficulty_calibrated FLOAT,  -- 0-1，后续由IRT校准（暂留空）
    
    -- 溯源信息
    source_entity_ids UUID[],  -- 生成该题使用的实体ID列表
    source_text_ids UUID[],    -- 生成该题使用的子块ID列表
    
    created_at TIMESTAMP DEFAULT NOW(),
    metadata JSONB DEFAULT '{}'::jsonb
);

CREATE INDEX idx_questions_document_id ON questions(document_id);
CREATE INDEX idx_questions_bloom_level ON questions(bloom_level);
```

## 三、核心处理流程

### 3.1 文档上传后的自动处理

```
文档上传完成（POST /api/documents）
    ↓
【触发】异步任务：process_document_graph(document_id)
    ↓
【步骤1】检查生命周期状态
    ├── 如果 status = 'unchanged' → 跳过（复用已有图谱）
    ├── 如果 status = 'new' 或 'modified' → 执行以下步骤
    └── 如果 status = 'deleted' → 移除子图（M2.9实现）
    ↓
【步骤2】实体提取（LLM）
    ├── 输入：该文档的所有子块内容（聚合）
    ├── 输出：实体列表（name + type + description）
    └── 存入 entities 表，关联 document_id
    ↓
【步骤3】关系提取（LLM）
    ├── 输入：子块内容 + 已提取的实体列表
    ├── 输出：关系列表（source → relation_type → target + description）
    └── 存入 relations 表，关联 document_id
    ↓
【步骤4】更新文档状态
    └── lifecycle_status = 'unchanged'
    └── processed_at = NOW()
```

### 3.2 实体提取 Prompt

```
[SYSTEM] 你是一位知识工程专家。请从以下教材内容中提取所有重要实体。

【输出格式要求】
你必须输出纯 JSON 数组，不允许包含任何其他内容：
[
  {"name": "实体名称", "type": "实体类型", "description": "简短描述（15字以内）"},
  ...
]

【实体类型】
- concept: 核心概念（如“自我意识”、“形式运算”）
- theorist: 心理学家/理论家（如“皮亚杰”、“埃里克森”）
- theory: 理论名称（如“认知发展阶段理论”）
- method: 研究方法（如“实验法”、“访谈法”）
- fact: 关键事实或研究发现

【提取规则】
1. 只提取对理解该章节必要的实体，不提取无关细节
2. 同一实体多次出现只提取一次
3. 描述应简洁，突出该实体的核心含义

【教材内容】
{aggregated_chunks}

【请开始提取实体】
```

### 3.3 关系提取 Prompt

```
[SYSTEM] 你是一位知识工程专家。以下是已从教材中提取的实体列表。请识别这些实体之间的关系。

【输出格式要求】
你必须输出纯 JSON 数组，不允许包含任何其他内容：
[
  {"source": "源实体名称", "target": "目标实体名称", "relation_type": "关系类型", "description": "关系描述（15字以内）"},
  ...
]

【关系类型】
- is_a: 上下位关系（如“自我意识” is_a “心理现象”）
- contains: 包含关系（如“自我意识” contains “自我概念”）
- causes: 因果关系（如“认知发展” causes “自我意识变化”）
- contrasts: 对比关系（如“皮亚杰” contrasts “维果茨基”）
- precedes: 时序关系（如“形式运算” precedes “后形式运算”）
- applies_to: 应用于（如“皮亚杰理论” applies_to “教育实践”）
- develops: 发展过程（如“自我评价” develops “自我概念”）

【实体列表】
{entities}

【教材内容参考】
{aggregated_chunks}

【请开始提取关系】
```

### 3.4 出题生成器（核心）

```
POST /api/questions/generate
```

**请求体**：

```json
{
  "document_id": "uuid",
  "entity_ids": ["entity1", "entity2"],  // 可选，指定实体
  "types": ["fill", "short_answer", "essay"],  // 可选
  "count_per_type": 3  // 每类题型生成数量
}
```

**处理流程**：

```
用户请求生成题目
    ↓
【步骤1】确定目标实体
    ├── 如果指定 entity_ids → 使用指定的实体
    └── 如果未指定 → 选取 entities 表中置信度 > 0.7 的实体（排除过于宽泛的）
    ↓
【步骤2】为每个目标实体检索事实链
    ├── 查询 relations 表，获取该实体直接关联的关系
    ├── 扩展1-2跳（通过 target_entity_id 反向查询）
    └── 将实体和关系组装为事实链（结构化文本）
    ↓
【步骤3】调用 LLM 生成题目
    ├── 输入：事实链 + 目标实体
    ├── 输出：题目数组（含 Bloom 层级和难度估计）
    └── 存入 questions 表
    ↓
【步骤4】返回生成的题目列表
```

### 3.5 出题 Prompt

```
[SYSTEM] 你是一位考研命题专家。以下是一组以【实体-关系-实体】三元组形式呈现的**事实链**，来源于教材。

【事实链】
{fact_chain}

【目标知识点】
{target_entity_name}: {target_entity_description}

【题目要求】
请基于上述事实链，生成 3 道填空题、2 道简答题、1 道论述题。

- 填空题：挖空位置必须是事实链中的关键实体或关系
- 简答题：要求对比或简述事实链中的关系
- 论述题：结合目标知识点展开论述

【输出格式】
纯 JSON 数组：
[
  {"type": "fill", "stem": "题干", "answer": "答案", "bloom_level": "层级", "difficulty_estimate": 0.5},
  ...
]

【Bloom 层级】
- remember: 识记（定义、名称、事实）
- understand: 理解（解释、举例、总结）
- apply: 应用（运用概念解决新问题）
- analyze: 分析（区分、组织、归因）
- evaluate: 评价（判断、批判、辩护）

【请开始生成题目】
```

### 3.6 校验规则

| 题型 | 校验规则 |
|------|----------|
| fill | `answer` 非空且长度 < 50 字符，`stem` 包含至少一个 "____" |
| short_answer | `answer` 长度 > 20 字符，`stem` 以 "简述" 或 "为什么" 开头 |
| essay | `answer` 长度 > 100 字符，`stem` 以 "论述" 或 "分析" 开头 |
| 所有 | `bloom_level` 在枚举值中，`difficulty_estimate` 在 0-1 之间 |

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/documents/{id}/entities` | GET | 获取文档的所有实体 |
