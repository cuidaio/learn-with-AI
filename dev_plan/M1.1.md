#### 新增/修改的表

**1. 新增 `section_blocks` 表（L1 宏观语义单元）**

```sql
CREATE TABLE section_blocks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    title TEXT,                           -- 从结构信号提取的标题
    content TEXT NOT NULL,                -- 完整语义单元内容
    level INTEGER,                        -- 1=章, 2=节, 3=小节, 0=纯语义聚合
    level_type VARCHAR(20),              -- 'chapter' | 'section' | 'subsection' | 'semantic'
    start_pos INTEGER NOT NULL,           -- 在 cleaned_text 中的起始位置
    end_pos INTEGER NOT NULL,             -- 在 cleaned_text 中的结束位置
    block_index INTEGER NOT NULL,         -- 文档内序号
    metadata JSONB DEFAULT '{}'::jsonb,   -- 包含 strategy_used, signal_confidence 等
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_section_blocks_document_id ON section_blocks(document_id);
CREATE INDEX idx_section_blocks_block_index ON section_blocks(document_id, block_index);
```

**2. 修改 `chunks` 表（重命名为 `paragraph_blocks`，L2 微观语义单元）**

```sql

ALTER TABLE paragraph_blocks ADD COLUMN end_pos INTEGER;
ALTER TABLE paragraph_blocks ADD COLUMN block_index INTEGER;

```

**3. 更新 `documents` 表**


### 三、分块引擎重写（`chunking.py`）

**删除旧函数**：
- `_build_parent_chunks()`（滑动窗口构建父块）
- `_link_child_to_parent()`（父子关联）

**新增核心函数**：

#### 3.1 `build_section_blocks(cleaned_text: str, signals: List[StructureSignal]) -> List[SectionBlock]`

**逻辑**：

1. **有可靠结构信号时**（`is_structure_reliable = True`）：
   - 以 `level 1` 信号（章标题）为主要边界
   - 若无 level 1，则以 `level 2` 信号（节标题）为边界
   - 每个 L1 块包含其边界内所有内容
   - L1 块标题取自对应的结构信号

2. **无可靠结构信号时**（`is_structure_reliable = False` 或信号列表为空）：
   - 使用 `SemanticChunker`，阈值取第 **40 百分位**（较高阈值，确保大块语义完整）
   - 不强行切分句子边界

3. **强制约束**：
   - 每个 L1 块 **500-3000 字符**
   - 低于 500 字符的块，与下一个块合并（除非是文档最后一个块，则与上一个合并）
   - 高于 3000 字符的块，**不强制切分**（因为它可能确实是一个完整的大章节，保留完整性优先于大小限制）

4. **返回** `List[SectionBlock]`，每个包含：
   - `id`（新生成 UUID）
   - `title`（若有标题）
   - `content`
   - `level`、`level_type`
   - `start_pos`、`end_pos`
   - `block_index`
   - `metadata`：记录 `aggregation_strategy`（`structural` / `semantic_high`）

#### 3.2 `build_paragraph_blocks(section_block: SectionBlock) -> List[ParagraphBlock]`

**逻辑**：

1. 在单个 L1 块内部，使用 `SemanticChunker`，阈值取第 **25 百分位**（较低阈值，产生更精细的块）
2. 允许块间 **100 字符重叠**
3. 强制约束：
   - 每个 L2 块 **200-1200 字符**
   - 低于 200 字符的块，与下一个块合并
   - 高于 1200 字符的块，强制按句子边界切分（使用递归字符分割器作为后备）

4. **返回** `List[ParagraphBlock]`，每个包含：
   - `id`（新生成 UUID）
   - `section_block_id`（关联父 L1 块）
   - `content`
   - `start_pos`、`end_pos`
   - `block_index`（在 L1 内部的序号）
   - `embedding`（由调用者填充）
   - `strategy`（`semantic_chunk` 或 `fixed_fallback`）

#### 3.3 `chunk_document(cleaned_text: str, signals: List[StructureSignal], is_structure_reliable: bool) -> ChunkResult`

**主入口函数**，串联上述流程：

```python
def chunk_document(cleaned_text: str, signals: List[StructureSignal], is_structure_reliable: bool) -> ChunkResult:
    # 1. 构建 L1 块
    section_blocks = build_section_blocks(cleaned_text, signals, is_structure_reliable)
    
    # 2. 在每个 L1 块内部构建 L2 块
    all_paragraph_blocks = []
    for section in section_blocks:
        paragraphs = build_paragraph_blocks(section, cleaned_text)
        # 将 section_block_id 填入每个 paragraph
        for p in paragraphs:
            p.section_block_id = section.id
        all_paragraph_blocks.extend(paragraphs)
    
    # 3. 返回结果
    return ChunkResult(
        section_blocks=section_blocks,
        paragraph_blocks=all_paragraph_blocks
    )
```
