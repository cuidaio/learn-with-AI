## CC，请执行以下任务：M2.7 — 配置解耦 + LLM平台独立配置

M2.6 已验收通过。当前问题：Embedding 和 LLM 共用一套 `OPENAI_BASE_URL`，导致换平台时牵一发动全身。本次任务将两者配置**彻底解耦**，让你可以独立切换 Embedding 和 LLM 的平台。

---

### 一、核心改动

**.env 配置拆分**

将原来的单一配置：

```env
OPENAI_BASE_URL=https://api.siliconflow.cn/v1/
OPENAI_API_KEY=sk-xxx
EMBEDDING_MODEL=Qwen/Qwen3-Embedding-4B
LLM_MODEL=deepseek-ai/DeepSeek-V4-Flash
```

拆分为两套独立配置：

```env
# ===== Embedding 配置 =====
EMBEDDING_BASE_URL=https://api.siliconflow.cn/v1/
EMBEDDING_API_KEY=sk-xxx
EMBEDDING_MODEL=Qwen/Qwen3-Embedding-4B

# ===== LLM 配置 =====
LLM_BASE_URL=https://api.deepseek.com/v1/
LLM_API_KEY=sk-xxx
LLM_MODEL=deepseek-chat
```

**兼容旧配置**：如果旧的 `OPENAI_BASE_URL` 存在，但新配置为空，自动回填到新配置。

### 三、配置兼容逻辑

在 `config.py` 中实现 `Settings` 类时，处理以下场景：

```python
# 场景1：新配置未设置，旧配置存在 → 自动回填
if not self.embedding_base_url and self.openai_base_url:
    self.embedding_base_url = self.openai_base_url
    self.embedding_api_key = self.openai_api_key
    self.llm_base_url = self.openai_base_url
    self.llm_api_key = self.openai_api_key

# 场景2：用户只改了 LLM，Embedding 保留旧平台 → 各自独立工作
# 场景3：用户只改了 Embedding，LLM 保留旧平台 → 各自独立工作
```

**原则**：旧的 `OPENAI_*` 变量可以作为通用回退，但新配置一旦设置，优先使用新配置。

### 五、测试要点

1. **场景A**：`.env` 只有旧配置（`OPENAI_*`）→ 系统正常启动，Embedding 和 LLM 走同一平台（向后兼容）
2. **场景B**：`.env` 有新配置（`EMBEDDING_*` 和 `LLM_*`）→ 两者独立工作，互不影响
