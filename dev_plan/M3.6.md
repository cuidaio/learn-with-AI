## 一、实体提取 Prompt 重写（核心改动）

### 1.1 新 Prompt

```
[SYSTEM] 你是一位考研心理学辅导老师，擅长从教材中提取可出题的知识点。

【任务】从以下教材内容中提取所有【被介绍过】的知识实体。

“被介绍”的定义：该内容在文本中至少满足以下任一条件：
1. 被明确定义（如“X是指……”“X是……”）
2. 被解释其特征或功能（如“X具有……特点”“X表现为……”）
3. 被分类或列举（如“X包括……”“X可分为……”）
4. 被赋予理论地位（如“X认为……”“X提出……”）
5. 作为章节标题或小节标题出现，且正文中有相关内容

【排除规则】
- 不要提取仅在举例中出现的名词（如“如焦虑、抑郁等情绪问题”中的“抑郁”）
- 不要提取数字、百分比、统计值
- 不要提取文献引用（如“Smith et al., 2020”）
- 不要提取过渡句中的修饰词

【可提取的实体类型】
- concept：被定义或解释的心理学术语
- theorist：被介绍的心理学家姓名（含其主要观点）
- theory：被阐述的理论名称
- method：被说明的研究方法名称
- fact：被特别强调的、可出题的事实性内容

【输出格式】
纯 JSON 数组：
[
  {"name": "实体名称", "type": "concept|theorist|theory|method|fact", "description": "该实体在原文中被介绍的核心内容（一句话）", "introduction_context": "原文中介绍该实体的关键句（完整引用）"}
]

【教材内容】
{chunk_content}

【请开始提取】
```

## 二、后处理：确定性丢弃

### 2.1 规则定义

```python
def post_process(entities: List[Dict]) -> List[Dict]:
    for entity in entities:
        # 规则1：纯数字或百分比 → 丢弃
        if re.match(r'^\d+\.?\d*%?$', entity['name']):
            entity['filter_action'] = 'discard'
            entity['filter_reason'] = 'numeric_value'
            continue
        
        # 规则2：文献引用格式 → 丢弃
        if re.search(r'\([\w]+\s*,\s*\d{4}\)', entity['name']) or \
           re.search(r'\(\d{4}\)', entity['name']):
            entity['filter_action'] = 'discard'
            entity['filter_reason'] = 'citation'
            continue
        
        # 规则3：检查 introduction_context 是否存在
        if not entity.get('introduction_context'):
            entity['filter_action'] = 'review'
            entity['filter_reason'] = 'no_context'
        else:
            entity['filter_action'] = 'keep'
            entity['filter_reason'] = 'passed'
    
    return [e for e in entities if e['filter_action'] != 'discard']
```

### 2.2 处理流程

```
LLM 输出实体列表
    ↓
后处理：
    ├── 纯数字/百分比 → discard
    ├── 文献引用 → discard
    ├── 无 introduction_context → review
    └── 有 introduction_context → keep
    ↓
保留 keep + review 实体存入数据库
```

### 字段说明

| 字段 | 说明 | 取值 |
|------|------|------|
| `introduction_context` | LLM 提供的原文介绍句 | 文本（完整引用） |

| `filter_reason` | 决策原因 | `passed` / `numeric_value` / `citation` / `no_context` |


### 4.2 交互逻辑

| 用户操作 | 系统行为 |
|----------|----------|
| 点击「确认保留」 | `filter_action` 变为 `keep`，实体进入知识图谱，可被出题使用 |
| 点击「标记丢弃」 | `filter_action` 变为 `discard`，实体不再出现在列表和出题中 |
| 点击「查看原文」 | 弹出原文片段预览，或跳转到原文对应位置 |
| 切换到「已过滤」分类 | 显示所有 `discard` 实体，可“撤销丢弃”（恢复为 `review`） |

### 4.3 出题时的实体筛选

出题生成器**只使用 `filter_action = 'keep'` 的实体**。`review` 和 `discard` 状态的实体不出题。


## 五、用户手动添加实体

### 5.1 入口

在文档阅读器（DocumentReader）中，用户选中文本 → 右键菜单增加选项：

```
┌─────────────┐
│ 复制        │
│ 高亮        │
│ 📌 标记为知识点  ← 新增
│ 基于此提问   │
│ 基于此出题   │
└─────────────┘
```

### 5.2 行为

用户点击「标记为知识点」后：

1. 弹出对话框：
```
┌─────────────────────────────────────────────────────────────┐
│  标记为知识点                                              │
│  ─────────────────────────────────────────────────────────  │
│  选中的文本：                                              │
│  "斯金纳通过实验提出了操作条件反射的概念，其核心是强化"   │
│                                                           │
│  实体名称：[操作条件反射  ]                                │
│  实体类型：[concept ▼]                                    │
│  描述：    [强化是操作条件反射的核心机制  ]                │
│                                                           │
│  [取消]                    [确认添加]                     │
└─────────────────────────────────────────────────────────────┘
```

2. 用户确认后，实体存入数据库：
   - `filter_action = 'keep'`（用户手动添加的实体默认信任）
   - `introduction_context = 选中的文本`
   - `source = 'manual'`（标记为手动添加）

### 5.3 数据模型补充字段

```sql
ALTER TABLE entities ADD COLUMN source VARCHAR(20) DEFAULT 'llm';  -- 'llm' | 'manual'
```
