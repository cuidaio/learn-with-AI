## 二、筛选/排序/搜索时中栏闪烁修复

### 2.1 问题
切换筛选条件后，整个中栏重新渲染，导致视觉闪烁。

### 2.2 解决方案

使用 Vue 的 `<keep-alive>` 缓存组件实例：

```vue
<!-- ContentRenderer.vue -->
<keep-alive>
  <component 
    :is="rendererComponent"
    v-if="contentData"
    :key="contentData.id + contentType"
    :data="contentData.data"
    :document-id="documentId"
    @entity-updated="onEntityUpdated"
  />
</keep-alive>
```

配合 `activated` 钩子，在组件重新激活时刷新数据，而不是销毁重建：

```javascript
// EntitiesView.vue
activated() {
  // 组件被 keep-alive 重新激活时刷新数据
  this.loadEntities()
}
```

## 三、实体生成后高亮自动更新

### 3.1 问题
实体确认/过滤后，文档中的高亮不更新，需关闭标签页重新打开。

### 3.2 解决方案

在实体审核/编辑/添加后，发出事件通知 `DocumentReader` 重新加载高亮：

```javascript
// EntitiesView.vue - 确认/丢弃/编辑后
const onEntityAction = async (entityId, action) => {
  await api.reviewEntity(entityId, action)
  emit('entity-updated')  // 通知父组件
}

// ContentRenderer.vue - 监听事件
const onEntityUpdated = () => {
  // 通知 DocumentReader 重新加载高亮
  documentStore.refreshHighlights(documentId)
}

// DocumentReader.vue - 监听刷新事件
watch(
  () => documentStore.highlightRefreshTrigger,
  () => {
    loadHighlightedDocument()
  }
)
```

## 四、阅读进度保留

### 4.1 问题
切换文档或重新打开文档页，滚动条回到顶部。

### 4.2 解决方案

在 `useContentStore` 中存储每个文档的阅读进度：

```javascript
// stores/useContentStore.js
{
  documentScrollPositions: {}  // { 'doc-123': 450, 'doc-456': 820 }
}
```

```vue
<!-- DocumentReader.vue -->
<script setup>
const scrollContainer = ref(null)

onMounted(() => {
  const savedPosition = contentStore.getScrollPosition(props.documentId)
  if (savedPosition && scrollContainer.value) {
    scrollContainer.value.scrollTop = savedPosition
  }
})

onUnmounted(() => {
  if (scrollContainer.value) {
    contentStore.saveScrollPosition(
      props.documentId, 
      scrollContainer.value.scrollTop
    )
  }
})
</script>
```

## 六、高亮悬浮分级解释（核心）

### 6.1 问题

| 问题 | 说明 |
|------|------|
| 悬浮只显示 type | 如“concept”，无助于理解 |
| 并非所有实体都需要解释 | 当前上下文已定义时，解释冗余 |
| 解释应该智能调用 | 优先使用其他文档中的“被介绍”定义 |

### 6.2 设计原则

> 解释一个实体，是为了帮助读者理解当前文本。如果当前文本已经给出了充分定义，解释就是冗余。如果当前文本只是“提及”而实体在其他地方被“定义”，解释才有必要。

### 6.3 分级逻辑

```
1. 检查当前上下文中是否已经定义该实体
   ├── 当前段落/附近句子包含定义信号（“是”“指”“即”“称为”）→ 不显示解释
   └── 当前上下文仅“提及”无定义 → 进入下一步

2. 检查该实体是否有跨文档的定义
   ├── 在 knowledge_nodes/entities 中查找该实体
   ├── 如果该定义来自当前文档 → 不显示（同一文档上下文已提供）
   └── 如果该定义来自其他文档 → 显示解释

3. 显示内容
   ├── 实体名称 + 类型标签
   ├── 简短解释（来自最佳 introduction_context）
   ├── 来源文档名
   └── “点击查看完整上下文”按钮（可选）
```

### 6.4 实现方案

```vue
<!-- DocumentReader.vue - 高亮悬浮逻辑 -->
<template>
  <span 
    v-for="highlight in highlights" 
    class="entity-highlight"
    @mouseenter="showTooltip(highlight, $event)"
    @mouseleave="hideTooltip"
  >
    {{ highlight.text }}
  </span>
  <div v-if="tooltipVisible" class="entity-tooltip" :style="tooltipPosition">
    <div class="tooltip-header">
      <span class="entity-name">{{ tooltipData.name }}</span>
      <span class="entity-type">{{ tooltipData.type }}</span>
    </div>
    <div class="tooltip-body">
      {{ tooltipData.definition }}
    </div>
    <div class="tooltip-footer" v-if="tooltipData.source">
      来源：{{ tooltipData.source }}
    </div>
  </div>
</template>

<script>
const showTooltip = (highlight, event) => {
  // 1. 检查当前上下文是否已定义
  const context = getHighlightContext(highlight)
  const hasLocalDefinition = detectDefinitionSignal(context)
  
  if (hasLocalDefinition) {
    // 不显示 tooltip（上下文已定义）
    return
  }
  
  // 2. 查找跨文档定义
  const entity = findEntity(highlight.entityId)
  if (!entity || !entity.introduction_context) {
    return
  }
  
  // 3. 判断是否跨文档
  if (entity.document_id === currentDocumentId) {
    // 同一文档的定义 → 不显示（用户可通过上下文理解）
    return
  }
  
  // 4. 显示 tooltip
  tooltipData.value = {
    name: entity.name,
    type: entity.type,
    definition: entity.introduction_context,
    source: entity.source_document_title
  }
  tooltipVisible.value = true
}
</script>
```
