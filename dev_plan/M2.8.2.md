## 一、核心设计变更：异步任务模式

### 1.1 设计原则

**点击「生成题目」创建任务，立即返回，后台异步执行，完成后通知。**

这是所有“创建型”操作的标准模式，后续M3组卷、M4批改均采用同一架构。

### 1.2 任务生命周期

```
pending → running → completed / failed
```

### 1.3 数据模型

```sql
CREATE TABLE tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_type VARCHAR(20) NOT NULL,  -- 'question_generation' | 'exam_composition' | 'grading'
    status VARCHAR(20) DEFAULT 'pending',  -- 'pending' | 'running' | 'completed' | 'failed'
    
    -- 任务参数（JSON）
    params JSONB NOT NULL,
    
    -- 执行结果
    result JSONB,  -- completed时存放结果
    error_message TEXT,  -- failed时存放错误信息
    
    -- 进度追踪
    total_steps INT,
    completed_steps INT DEFAULT 0,
    current_step_description TEXT,
    
    -- 时间戳
    created_at TIMESTAMP DEFAULT NOW(),
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    
    metadata JSONB DEFAULT '{}'::jsonb
);

CREATE INDEX idx_tasks_status ON tasks(status);
CREATE INDEX idx_tasks_task_type ON tasks(task_type);
CREATE INDEX idx_tasks_created_at ON tasks(created_at DESC);
```

### 1.4 API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/tasks/questions` | POST | 创建出题任务，立即返回 `task_id` |
| `/api/tasks/{id}/status` | GET | 查询任务状态（含进度） |
| `/api/tasks/{id}/result` | GET | 获取任务结果（completed时返回题目列表） |
| `/api/tasks` | GET | 获取所有任务列表（支持按类型/状态过滤） |
| `/api/tasks/{id}/cancel` | POST | 取消运行中的任务（可选） |

## 二、修正：关系类型不作为考查项

### 2.1 问题

原方案中，出题的事实链可能包含关系类型标签（如 `contains`、`causes`），LLM 可能误将这些元数据标签作为考查对象生成“×× contains 什么？”之类的无效题。

### 2.2 修正

**在事实链构建中，关系类型只作为连接词描述，不作为独立考查对象。**

- 事实链格式：`源实体 [关系类型描述] 目标实体`
  - 例：`自我意识 [包含] 自我概念`
  - 关系类型在 Prompt 中作为连接词，不出题
- Prompt 中明确标注：**“以下三元组中的关系类型（如 contains、causes）仅用于描述实体间的连接关系，不是考查对象”**

### 2.3 代码改动位置

`question_generator.py` 中 `format_fact_chain()` 函数：

```python
def format_fact_chain(relations: list) -> str:
    """
    将关系列表格式化为事实链字符串。
    关系类型作为连接词，不作为独立实体。
    """
    lines = []
    for r in relations:
        source = r.get('source_name', '')
        target = r.get('target_name', '')
        rel_type = r.get('relation_type', '').replace('_', ' ')
        # 关系类型只作为连接词
        lines.append(f"{source} [ {rel_type} ] {target}")
    return "\n".join(lines)
```

- 用户可手动刷新任务列表

## 四、并行化出题

### 4.1 核心实现

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

# 默认并发数为 3（用户要求）
DEFAULT_MAX_WORKERS = 3

def execute_question_task(task_id: UUID, params: dict):
    """后台执行出题任务。"""
    entities = params.get('entity_ids', [])
    # 其他参数...
    
    results = []
    failed = []
    
    with ThreadPoolExecutor(max_workers=DEFAULT_MAX_WORKERS) as executor:
        futures = {
            executor.submit(generate_for_entity, entity_id, params): entity_id
            for entity_id in entities
        }
        
        for future in as_completed(futures):
            entity_id = futures[future]
            try:
                questions = future.result(timeout=120)
                results.extend(questions)
                update_task_progress(task_id, 1)
            except Exception as e:
                failed.append({"entity_id": entity_id, "error": str(e)})
    
    # 保存结果到 tasks 表
    complete_task(task_id, results, failed)
```

### 4.2 配置

在 `config.py` 中：

```python
QUESTION_WORKERS: int = 3  # 默认并发数
QUESTION_TIMEOUT: int = 120  # 单实体超时时间（秒）
```
