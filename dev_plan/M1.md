### 一、本次任务的核心设计原则（必读）

1. **结构是恩赐，不是依赖**：如果输入文本包含清晰的 Markdown 标题（`#`、`##`等）或数字序号，系统应利用它们作为切分锚点。如果格式混乱或缺失，系统应退化为纯语义切分，绝不崩溃。

2. **OCR 噪声是常态，不是意外**：来自 MinerU 等工具的 Markdown 输出可能包含：标题前 `#` 数量不一致（同级标题一个用 `##`、另一个用 `###`）、页码残留、断行异常、图表标记残留。系统必须清洗这些噪声。

3. **父子块架构是底线保障**：无论切片策略如何，系统必须同时维护两种粒度的块。检索命中子块（精度），回答引用父块（上下文完整性）。这确保了即使切分不完美，上下文也不丢失。

### 三、预处理模块（`backend/app/core/preprocess.py`）——处理脏输入

CC 必须实现以下函数，按顺序执行：

#### 3.1 `normalize_whitespace(text: str) -> str`
- 将所有连续空白字符（空格、制表符、零宽字符）压缩为单个空格
- 移除行首行尾空白
- 不修改换行符

#### 3.2 `fix_broken_lines(text: str) -> str`
- 检测异常断行模式：当前行不以句号/问号/感叹号/冒号/分号结尾，且下一行不是空行，且下一行首字母不是大写（中文则检测是否以标点开头）
- 合并这些被错误断开的行
- **注意**：如果输入是 Markdown，需跳过代码块和表格区域

#### 3.3 `remove_page_numbers(text: str) -> str`
- 删除以下模式的行（整行匹配）：
  - 纯数字（如 `123`）
  - `- 1 -`、`· 5 ·` 等页码装饰
  - 中文页码如 `第3页`
- 保留正文中的数字

#### 3.4 `extract_structure_signals(text: str) -> list[dict]`
**这是核心函数：扫描文本，提取所有“弱结构信号”作为切分候选锚点。**

检测以下模式（正则匹配），返回信号列表：

| 信号类型      | 正则模式                                   | 置信度                                     | 说明                                          |
| ------------- | ------------------------------------------ | ------------------------------------------ | --------------------------------------------- |
| Markdown 标题 | `^(#{1,6})\s+(.+)$`                        | 高（`#`数量一致时）、中（`#`数量不一致时） | 如果同一文档中 `#` 数量混乱，降级为中等置信度 |
| 中文章节号    | `^第[一二三四五六七八九十百千万]+章\s*`    | 高                                         | 如“第三章 认知心理学”                         |
| 中文序号      | `^[（(]?[一二三四五六七八九十][)）]\.?\s*` | 中                                         | 如“一、”“（一）”                              |
| 数字序号      | `^\d+\.\s*`                                | 中                                         | 如“1. ”“2. ”                                  |
| 空行密集区    | `\n{3,}`                                   | 低                                         | 仅作为辅助参考，不单独作为切分依据            |

**关键逻辑**：
- 如果检测到 **≥3个 Markdown 标题**且 `#` 数量模式一致（如全部是 `##` 或全部是 `###`），则判定为“结构可靠”，标题置信度设为“高”
- 如果 `#` 数量混乱（如一个 `##`、下一个 `###`、再下一个 `##`），则判定为“结构不可靠”，所有标题置信度降为“中”，作为辅助锚点而非强制切分点
- 对高置信度锚点：在对应位置强制切分
- 对中置信度锚点：作为语义切分的候选边界，与语义切分结果取并集
- 对低置信度锚点：仅在语义切分无结果时使用

#### 3.5 `clean_markdown_artifacts(text: str) -> str`
- 移除图像标记：`![](...)` 或 `<img ...>`
- 移除表格标记：`| --- |`、`| 单元格 |`
- 移除脚注标记：`[^1]`、`[注]`
- **保留表格内容**（移除格式标记但保留文本内容），只移除标记符本身
- 移除 LaTeX 公式标记：`$...$` 和 `$$...$$` 移除标记，保留公式文本

#### 3.6 主入口函数 `preprocess_document(raw_text: str) -> PreprocessResult`

```python
from dataclasses import dataclass
from typing import List

@dataclass
class StructureSignal:
    position: int  # 字符位置
    signal_type: str  # "markdown_heading" | "chinese_chapter" | "chinese_ordinal" | "numeric_ordinal"
    confidence: str  # "high" | "medium" | "low"
    content: str  # 标题内容
    level: int  # 仅对 Markdown 标题有效

@dataclass
class PreprocessResult:
    cleaned_text: str
    signals: List[StructureSignal]
    is_structure_reliable: bool
```

**处理流程**：
```
raw_text
  → normalize_whitespace()
  → fix_broken_lines()
  → remove_page_numbers()
  → clean_markdown_artifacts()
  → extract_structure_signals()  # 同时判定 is_structure_reliable
  → 输出 PreprocessResult
```

### 四、分块引擎（`backend/app/core/chunking.py`）——自适应策略

#### 4.1 分块策略选择器

```python
def select_chunking_strategy(preprocess_result: PreprocessResult) -> str:
    """
    返回: "structural" | "semantic" | "hybrid"
    """
    if preprocess_result.is_structure_reliable and len(preprocess_result.signals) >= 3:
        return "structural"
    elif len(preprocess_result.signals) >= 1:
        return "hybrid"
    else:
        return "semantic"
```

#### 4.2 三种分块策略

**策略 A：Structural（结构可靠时）**

按高置信度信号（Markdown 标题、中文章节号）的位置强制切分。每个切片以标题为起点，到下一个标题之前为止。

- 如果某个切片超过 `MAX_CHUNK_SIZE`，对该切片内部递归使用语义分块（策略 C）进行细分
- 确保每个切片至少 `MIN_CHUNK_SIZE`，不足则与相邻切片合并

**策略 B：Semantic（结构不可靠时）**

完全不使用结构信号，纯语义分块：

1. 使用 `SemanticChunker`（LangChain Experimental）
2. 计算句子嵌入（调用 Embedding API）
3. 计算相邻句子相似度分布，取 **第30百分位** 作为动态阈值
4. 相似度低于阈值处切分
5. 强制约束：最小 `MIN_CHUNK_SIZE`，最大 `MAX_CHUNK_SIZE`

**策略 C：Hybrid（存在弱信号时）**

1. 先用中置信度信号位置作为“软边界”，将文本预切分为大段
2. 对每个大段，执行语义分块（策略 B）
3. 语义分块的切分点如果与软边界距离 < 50 字符，则对齐到软边界
4. 强制约束：最小 `MIN_CHUNK_SIZE`，最大 `MAX_CHUNK_SIZE`

#### 4.3 父子块构建（所有策略统一执行）

无论采用哪种分块策略，最终都要构建父子块架构：

**父块生成（滑动窗口，不依赖结构）：**
- 窗口大小：`PARENT_CHUNK_SIZE`（默认2000字符）
- 步长：`PARENT_CHUNK_SIZE - PARENT_CHUNK_OVERLAP`（默认1800字符）
- 从文档开头滑动，生成一系列父块
- 父块不要求语义完整（它是“上下文容器”，不是“语义单元”）

**子块生成（上述策略 A/B/C 的输出）：**
- 子块是语义完整的精细单元
- 每个子块记录其覆盖的字符范围 `start_pos` 和 `end_pos`

**关联建立：**
- 对每个子块，找到覆盖其 `start_pos` 的父块，建立 `parent_chunk_id` 关联
- 如果子块跨越多个父块（通常不应发生），则选择覆盖范围最大的父块

#### 4.4 分块结果存储结构

```python
@dataclass
class ChunkResult:
    chunk_id: str  # UUID
    content: str
    chunk_index: int  # 子块在文档中的序号
    start_pos: int
    end_pos: int
    metadata: dict  # 包含 { "strategy": "structural"|"semantic"|"hybrid", "signal_type": 可选 }
    parent_chunk_id: str  # 关联到父块
    embedding: list[float]  # 向量化后的结果

@dataclass
class ParentChunkResult:
    parent_chunk_id: str
    content: str
    start_pos: int
    end_pos: int
    child_ids: list[str]  # 包含的子块ID列表
```

### 六、Embedding 客户端（`backend/app/core/embeddings.py`）

与之前版本相同，但增加批量处理能力（用于 SemanticChunker）：

```python
from openai import OpenAI
from app.core.config import settings

_client = None

def get_embedding_client():
    global _client
    if _client is None:
        _client = OpenAI(
            api_key=settings.openai_api_key,
            base_url=settings.openai_base_url
        )
    return _client

def embed_text(text: str) -> list[float]:
    client = get_embedding_client()
    response = client.embeddings.create(
        model=settings.embedding_model,
        input=text
    )
    return response.data[0].embedding

def embed_batch(texts: list[str]) -> list[list[float]]:
    """批量向量化，用于 SemanticChunker"""
    if not texts:
        return []
    client = get_embedding_client()
    response = client.embeddings.create(
        model=settings.embedding_model,
        input=texts
    )
    return [data.embedding for data in response.data]
```

### 七、后端接口详细设计

#### 7.1 `POST /api/documents` —— 上传并处理文档

**请求体（JSON）：**

```json
{
  "title": "普心第一章-绪论",
  "raw_text": "心理学是研究心理现象及其规律的科学..."
}
```

**后端处理流程（完整）：**

1. 接收请求，生成 `document_id`（UUID）
2. 调用 `preprocess_document()` 预处理原始文本
3. 将 document 记录插入数据库（状态为 `processing`）
4. 调用 `select_chunking_strategy()` 选择分块策略
5. 执行分块（策略 A/B/C），生成子块列表
6. 生成父块（滑动窗口）
7. 对每个子块：
   a. 调用 `embed_text()` 或 `embed_batch()` 生成向量
   b. 存入 `chunks` 表，关联对应的 `parent_chunk_id`
8. 将父块存入 `parent_chunks` 表
9. 更新 document 状态为 `completed`，记录 `total_chunks` 和 `total_parent_chunks`

**响应示例：**

```json
{
  "status": "success",
  "document_id": "550e8400-...",
  "title": "普心第一章-绪论",
  "total_sub_chunks": 12,
  "total_parent_chunks": 5,
  "strategy_used": "hybrid",
  "total_characters": 5840,
  "is_structure_reliable": false
}
```

**错误处理：**
- `raw_text` 为空或全空白：返回 400
- Embedding API 调用失败：status 标记为 `failed`，返回 503，但保留已处理的数据
- 如果预处理后文本为空（全是噪声）：返回 400 `{"detail": "预处理后无有效文本内容"}`
