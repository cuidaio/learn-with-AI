### 一、界面布局（双栏设计）

**整体布局**：左右两栏，左侧占 30%，右侧占 70%。

**左侧栏：文档列表**
- 顶部标题：「📚 我的资料库」
- 每个文档显示：
  - 文档标题
  - 状态标签：`已完成`（绿色） / `处理中`（黄色） / `失败`（红色）
  - 子块数量
  - 复选框（用于多选）
- 底部：「📤 上传新文档」按钮（点击后弹出上传对话框）
- 底部统计：「已选 N 个文档」

**右侧栏：对话区**
- 顶部标题：当前选中文档名称（如「已选：青少年个性和社会性的发展 + 2 个其他文档」）
- 中间区域：对话消息流（纵向排列）
  - 用户消息：右对齐，浅灰背景
  - AI 消息：左对齐，白色背景，包含：
    - 回答正文（`【来源编号】` 高亮为可点击标签）
    - 「📖 引用来源」折叠区域（默认展开），显示：
      - 编号、章节标题、相关度分数
      - 点击后打开对应位置（暂不实现跳转，仅显示）
- 底部：输入框 +「发送」按钮（固定于底部）
  - 输入框 placeholder：「输入你关心的问题...」
  - 发送按钮：主色（蓝色），点击后触发提问
  - 快捷键：Ctrl+Enter 或 Command+Enter 发送

**空状态**：
- 左侧无文档：「暂无文档，点击「上传新文档」开始学习」
- 右侧无对话：「选择一个文档后开始提问」


### 二、跨文档检索

**逻辑**：
1. 用户通过复选框选择 1 个或多个文档
2. 输入问题，点击发送
3. 前端调用 `POST /api/ask`，传入 `document_ids`（数组）而非单个 `document_id`
4. 后端修改：遍历所有选中文档的 `sub_chunks` 表，分别检索后合并结果
5. 合并策略：
   - 从每个文档取 `top_k` 个最相关子块
   - 最终按相关度排序，取前 `top_k` 个作为上下文
6. 其他逻辑不变（聚合 L1 块、组装 Prompt、LLM 生成回答）

**后端接口调整**：

请求体：
```json
{
  "document_ids": ["uuid1", "uuid2", "uuid3"],
  "question": "自我意识有什么特点？",
  "top_k": 5
}
```

响应体不变。`sources` 中新增 `document_title` 字段，方便用户区分来源文档。

**单文档兼容**：
- 如果只选 1 个文档，行为与当前一致
- 如果选 0 个文档，「发送」按钮禁用，提示「请至少选择一个文档」

```javascript
  // 上传

```

**对话历史持久化**：
- 不刷新丢失（当前无持久化需求）
- 刷新页面时清空（后续可考虑 localStorage）


### 四、交互反馈

**提问过程中**：
1. 用户点击发送 → 输入框禁用，按钮显示「思考中...」
2. 用户消息立即出现在对话流中（灰色，右对齐）
3. 1 秒后，AI 消息区域出现「正在思考...」加载动画（三个点跳动）
4. 返回结果后，加载动画替换为回答正文
5. 输入框启用，按钮恢复为「发送」

**错误处理**：
- 网络错误：显示「网络连接失败，请重试」
- 后端错误：显示错误信息（如「文档未找到」）
- 超时：显示「回答超时，请重试」
