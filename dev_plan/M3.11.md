## 二、持久化改造（前置基础）

### 2.1 PostgreSQL 数据卷

**确认 `docker-compose.yml` 中 postgres 服务已配置持久化卷：**

```yaml
services:
  postgres:
    image: pgvector/pgvector:pg16
    volumes:
      - postgres_data:/var/lib/postgresql/data
    # ...

volumes:
  postgres_data:
    driver: local
```

**验收**：执行 `docker-compose down -v` 后，再 `docker-compose up -d`，之前上传的文档和实体数据应仍然存在。

### 2.2 配置数据模型（新增）

```sql
CREATE TABLE app_config (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    key VARCHAR(100) NOT NULL UNIQUE,
    value JSONB NOT NULL,
    updated_at TIMESTAMP DEFAULT NOW()
);
```

**种子数据**：

```sql
INSERT INTO app_config (key, value) VALUES 
('embedding', '{"base_url": "https://api.siliconflow.cn/v1/", "api_key": "", "model": "Qwen/Qwen3-Embedding-4B"}'),
('llm', '{"base_url": "https://api.deepseek.com/v1/", "api_key": "", "model": "deepseek-chat"}')
ON CONFLICT (key) DO NOTHING;
```

### 2.3 配置加载逻辑

**后端启动时从数据库加载配置，覆盖 `.env` 中的默认值：**

```python

    """启动时从数据库加载配置，覆盖环境变量"""
    # 如果数据库未初始化，使用 .env 默认值
    # 否则读取 app_config 表覆盖
```

### 3.3 API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/config` | GET | 获取当前配置（API Key 脱敏） |
| `/api/config` | PUT | 更新配置 |
| `/api/config/test` | POST | 测试连接（验证 Base URL + API Key + Model） |
| `/api/config/reset` | POST | 重置为默认配置 |

### 3.4 测试连接逻辑

```python
# POST /api/config/test
# 入参：{"type": "embedding" | "llm", "base_url": "...", "api_key": "...", "model": "..."}
# 行为：
# 1. 用提供的参数调用对应的 API（如 embeddings 或 chat completion）
# 2. 返回：{"success": true, "latency": 0.3} 或 {"success": false, "error": "..."}
```
